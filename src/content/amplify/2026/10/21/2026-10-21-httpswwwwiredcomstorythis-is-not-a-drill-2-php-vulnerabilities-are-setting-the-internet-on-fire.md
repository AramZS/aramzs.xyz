<div><div class="BaseText-fEwdHD SplitScreenContentHeaderDek-juwmcJ hhRWTn bFhTNF">The PHP Foundation has revealed two serious vulnerabilities that could impact millions of websites. Security experts warn that failure to quickly patch the flaws could have dire consequences.</div><figure><img alt="‘This Is Not A Drill Critical PHP Vulnerabilities Are Setting the Internet on Fire" class="ResponsiveImageContainer-dkeESL cQPiWi responsive-image__image" src="https://media.wired.com/photos/6ad8c3abc81397fca509f3d6/3:2/w_2560%2Cc_limit/102126-PHP-Breakdown.gif"/><figcaption>Photo-Illustration: Wired Staff; Getty Images</figcaption></figure><div class="body__inner-container"><p>Internet security and web administration teams around the world are scrambling to prevent widespread disaster. On Wednesday, the developers behind the much-used PHP programming language released emergency security updates designed to fix critical flaws that could be exploited to allow attackers to gain dangerous remote control of victim systems.</p><p class="paywall">The PHP Foundation <a class="external-link text link" href="https://www.php.net/index.php#2026-10-20-1">detailed</a> the two critical vulnerabilities—<a class="external-link text link" href="https://nvd.nist.gov/vuln/detail/cve-2026-109618">CVE-2026-109618</a> and <a class="external-link text link" href="https://nvd.nist.gov/vuln/detail/cve-2026-109619">CVE-2026-109619</a>—which impact “all PHP installations serving web requests” going back to PHP version 5, released in July 2004. However, only PHP 8.2 and newer are still supported and will receive patches, according to the alert. The PHP Foundation noted, though, that some PHP distributions and third-party vendors still produce legacy fixes. The caveat is significant, because ubiquitous and foundational web layers like PHP can persist forgotten and un-updated in historic internet infrastructure.</p><div></div><div></div><p class="paywall">“There are no complete mitigations, updating is the only safe choice,” the PHP Foundation wrote in its advisories. Security experts warn of the potential dire consequences of overlooking unpatched systems.</p><div class="Container-ioqmpI jzsvml"></div><p class="paywall">“This is not a drill,” says Lukasz Olejnik, an independent security consultant and visiting senior research fellow at King’s College London. Since its development in the 1990s, PHP has evolved into an essential scripting language for web development and is used across vast swaths of the internet in websites and software. Everything from publishing systems like WordPress and Drupal to e-commerce platforms like Adobe’s Magento are built on PHP.</p><p class="paywall">Olejnik likens the widespread use of the programming language to critical infrastructure.</p><p class="paywall">“The impact is enormous,” he says of PHP’s security flaws, adding that millions of systems could be impacted. “Especially if attackers would turn to exploiting these vulnerabilities fast. Worst case is wormable malware affecting big chunks of the internet.”</p><p class="paywall">The overriding fear for security teams and developers is that malicious hackers could quickly jump upon the vulnerabilities and begin exploiting deployments before they are fixed. Internet infrastructure company Cloudflare <a class="external-link text link" href="https://x.com/dok2001/status/2112811965735202970">reported</a> it was “seeing early attacks emerging” before the PHP Foundation had detailed the vulnerabilities and released fixes. “We expect mass attacks to start within 15 minutes of the release,” security firm Sansec <a class="external-link text link" href="https://sansec.io/research/php2shell">wrote</a> ahead of the fixes, which were released just before 10 am ET on Wednesday.</p><p class="paywall">“Most of the web runs on PHP and this bug is in a file upload interface that’s like a front door with no lock,” says longtime security and compliance consultant Davi Ottenheimer. “An attacker does not need to know which site they are hitting or even the actual software it runs. They send one crafted upload to any server they can find, and that is the entire attack.”</p></div><div class="body__inner-container"><p class="paywall">Ahead of the updated versions of PHP becoming available, some organizations took their websites offline as a precautionary measure. Multiple sites belonging to the Finnish government, including the National Land Survey, were inaccessible, according to <a class="external-link text link" href="https://yle.fi/a/74-20252600">reports</a>. French government websites and the Port of Rotterdam’s website were also offline, according to <a class="external-link text link" href="https://bsky.app/profile/raphae.li/post/3myf6l3slzs2w">Reuters</a>.</p><p class="paywall">“Everybody should patch immediately, exploitation may happen very fast and at a scale,” says Olejnik. “AI makes exploiting such vulnerabilities of immediate importance. Like, indeed, a minute or so.”</p><p class="paywall">Security company Wiz, which is owned by Google, <a class="external-link text link" href="https://www.wiz.io/blog/php2shell-php-rce">claimed</a> its researchers discovered the vulnerabilities in PHP partially using AI tools, while <a class="external-link text link" href="https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/">OpenAI</a> and security firm <a class="external-link text link" href="https://calif.io/php2shell.x/">Calif</a> also say they independently discovered the issues and worked together. Dubbing an exploitation demonstration php2shell , the Wiz researchers write that in some cases the vulnerabilities can be exploited “fairly easily.”</p><p class="paywall">“The vulnerabilities can allow unauthenticated attackers to execute code on affected servers or read sensitive process memory,” Wiz writes in its research. “That memory may contain passwords, authentication tokens, API keys and certificates belonging to other requests or the server itself.”</p><p class="paywall">Details of the upcoming vulnerabilities first appeared from the maintainers behind PHP on October 20. In a <a class="external-link text link" href="https://www.first.org/cvss/v4.0/specification-document">short post</a> on the PHP website, the PHP Foundation wrote it was giving “advance notice” of the security flaws and upcoming release of the fixes. While omitting specific details about the vulnerabilities or the versions impacted, it said both flaws are considered to have a “critical” 9.2 score out of 10 on the Common Vulnerability Scoring System (CVSS).</p><p class="paywall">“We reserve the right to release earlier should details of either vulnerability become public, or should evidence of active exploitation appear in the wild,” the security warning on the PHP site <a class="external-link text link" href="https://www.first.org/cvss/v4.0/specification-document">said</a> ahead of Wednesday’s release. According to reports from <a class="external-link text link" href="https://www.bleepingcomputer.com/news/security/php-warns-admins-of-two-critical-flaws-emergency-patches-coming-tomorrow/">Bleeping Computer</a> and <a class="text link" href="https://arstechnica.com/security/2026/10/php-maintainers-tell-web-devs-to-prepare-themselves-for-critical-security-patches/">Ars Technica</a>, some details about the vulnerabilities may have leaked before they were due to officially be published.</p></div><div class="body__inner-container"><p class="paywall">The early warning from the PHP Foundation may have given some developers, security teams, and companies enough of a heads up to start preparing to update systems using PHP. Ahead of the details being published, warnings from the EU’s Computer Emergency Response Team (EU-CERT) and Australia's cybersecurity agency said IT teams should be prepared to update their systems as soon as possible, with the potential for websites to be taken offline while fixes are applied.</p><p class="paywall">Similarly, the UK’s National Cyber Security Center (NCSC), published an <a class="external-link text link" href="https://www.ncsc.gov.uk/news/critical-security-issue-affecting-php">alert</a> saying organizations should “prepare for immediate updating of systems” using PHP. “Where immediate remediation is not feasible, organizations should consider taking the system offline until it can be fully mitigated,” the agency wrote online.</p><p class="paywall">The NCSC advises that organizations and businesses should identify systems running PHP across their tech infrastructure. There should be a particular focus on systems using PHP that are connected to the internet, including monitoring them for any potential exploitation. The next step is applying PHP updates as they are available and monitoring for updates from software companies as they may use PHP within their apps or services.</p><p class="paywall">“If you find signs of compromise, isolate the system, preserve your web server and PHP logs, and report it to your local FBI field office,” Brett Leatherman, the FBI’s cyber assistant director <a class="external-link text link" href="https://lnkd.in/p/eKuqKj8k">posted</a> online. “Those reports help us identify the actors involved and warn other organizations before they become victims.”</p></div></div>
