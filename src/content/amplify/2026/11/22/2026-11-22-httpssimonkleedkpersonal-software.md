<h2>Why make personal software</h2>
<p>I’ve been making personal software for as long as I can remember. I worked on a Terraria-like game a little after Terraria came out over a decade ago, and it took weeks of evenings to get a playable prototype. Now almost anything has <em>something</em> within a few hours.</p>
<p>We could obviously just play the original, which I still have on Steam, yet making <em>ours</em> is much more fun, and you can shape it exactly how you want.</p>
<p>Clay Shirky called this <a href="http://www.shirky.com/writings/situated_software.html">situated software</a>, which “is personal from its inception.” Robin Sloan made <a href="https://www.robinsloan.com/notes/home-cooked-app/">an app for his family</a> and wrote that programming this way is “a different activity altogether, just as cooking at home is really nothing like cooking in a commercial kitchen.”</p>
<p>My 4-year-old, our youngest, had a hard time with mouse and keyboard. I happened to have a pair of Switch Joy-Cons, so I added support for that after our first session. We play once a week, then they draw me something they want to see in the game, and I build some of it. A robot that scares zombies away with sound waves, trains, and countless others.</p>
<p>I’ve always created personal software; a database for myself, Shopify integrations for my wife’s business, a music studio for my son. I have more projects than I remember, sometimes I forget and rebuild things a decade later.</p>
<p>I don’t know if Terraria has a character studio, but I thought my kids would love to choose the hair and the skin color themselves, so we added it.</p>

<h2>Orchestrating agents</h2>
<p>For most of my longer projects, the <a href="https://opentui.com">OpenTUI</a> library included, I work in one main session that I pin and rename. I talk to it, and it keeps track of the project. Subagents do the implementation, each in its own worktree, other subagents review it, and the main session merges them. Burrow has two of these sessions: BURROW for the game and SCORE for the music.</p>
<p>Many of my chats with the main session happen away from the computer. The <a href="https://opencode.ai/mobile">OpenCode iOS</a> on my phone has a live audio session I can talk to, and it passes what I say on to the main session. I asked for the character studio by voice. What I say is usually a few sentences, and the main session writes a brief for a subagent from it.</p>
<figure><p>I think another task which would be cool to add is a playable character studio, or I like the playable characters, so you can edit them. Currently they are randomized, so the hair, skin color, et cetera. But for my kids they’d love playing around with adjusting those kinds of things. Adding that in a sub agent session. <p>Most of what I tell the main session is how something feels. When I said the world felt samey, its brief asked for a way to measure that, so an agent could show its change had helped. When I said the game’s moon felt flat and small, not like a planet, I got a larger moon with hills, and it still didn’t feel like a planet. Before the next try the main session asked me what I meant by a planet. You can walk all the way around the moon it built after that.</p>

<h2>Keep everything in text</h2>
<p>I keep as much of the game as I can in code and text, because that is what an agent can read and change. Burrow is written in Zig on top of Raylib, with no external game engine. It is about 220,000 lines of Zig.</p>
<p>A host process runs the world, and each player’s game sends it input and draws what comes back. The host builds without the graphics library, so tests can run the whole game without opening a window and play it the way a player would.</p>
<p>There are no sprite files either. Code draws every sprite when the game starts.</p>

<p>In my earlier games I ended up building tools to make the music. <a href="https://simonklee.dk/synth/">Studio</a> is one of those tools, a music program pulled out into a project of its own the week before I started Burrow. An agent writes a song as a file and renders it, and I can open the same file in Studio and play it. My son and I also use it to practice piano.</p>

<h2>Remaking the world</h2>
<p>In the first days I kept changing how worlds are generated, and my kids were mostly about playing the one world we had started. So the game keeps track of what we build and dig. When the layout of the world changes, it makes a new world from the same seed and puts our house and whatever else we built into it, with our chests and the townsfolk who live with us. Then it says “The Valley Has Changed” and, under it, “Your home stands”.</p>
<p>The only important thing to keep is the house. The rest can change. Later the map got wider, and across the eastern sea there is a mushroom country. From our beach you can see its largest cap on the horizon.</p>
