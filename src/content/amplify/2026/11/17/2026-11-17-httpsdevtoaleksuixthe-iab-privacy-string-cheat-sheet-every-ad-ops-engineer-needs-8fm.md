<p>On <a href="https://iabtechlab.com/press-releases/iab-tech-lab-expands-global-privacy-frameworks-with-gpp-updates-and-ddrf-v2-release/">23 October 2025</a> IAB Tech Lab opened public comment on H2 2025 Global Privacy Platform updates: four new U.S. state sections and a rearchitected state-string layout with explicit section headers. That is not a CMP banner story. It is a wire-format story. The same month, traffickers still paste TC Strings into <code>gpp</code>, leave <code>us_privacy=1YNN</code> on CM360 pixels that expect GPP National, and ship OpenRTB bids where <code>regs.gpp_sid</code> survives a hop but <code>regs.gpp</code> does not. Every one of those URLs can look "privacy complete" in a spreadsheet while the downstream callee runs the wrong decoder.</p>
<p>This sheet is for ad ops and bid engineers who own the live tag URL, the Floodlight path, or the OpenRTB <code>regs</code> object and need one place to map <strong>parameter name → grammar → where it must land</strong>. One malformed field is never the whole job; the job is knowing which family you actually have before you argue with fill or attribution.</p>

<p>OpenRTB and the pixel are parallel hops, not aliases. A CMP can be correct in the page and still wrong on the request the vendor logs if the ad-server macro never expanded. Floodlight-style path parameters count the same as query keys: if the string is not on the HTTP request the collector sees, it does not exist for billing or restriction logic.</p>
<p>For the October GPP release specifically, new state sections and subsection headers change what parsers must expect inside a type-3 container. Our <a href="https://rtblint.org/blog/gpp-new-sections-2026/">write-up on the new sections and OpenRTB <code>regs.gpp</code></a> tracks what landed in that comment package; your CMP version and your bid adapter version can drift on different calendars.</p>
<h2>   Three rows that validate and still fail in production </h2>
<p><strong><code>gdpr_consent=1</code>.</strong> Alphabet and base64 validators green-light it. A TC decoder rejects it immediately because there is no version-2 bitfield and no purpose vector. Google tags interpret <code>gdpr=1</code> as "TC applies"; an empty or numeric placeholder is how personalized ads quietly turn off while the tag still "has a consent param."</p>
<p><strong>TC String in <code>gpp</code> with <code>gpp_sid=2</code>.</strong> The blob is long, base64-safe, and familiar. Decoded header type is <strong>2</strong> (TC), not <strong>3</strong> (GPP). Campaign Manager 360's own documentation says TCF strings sent through GPP are not accepted on that hop; the section id names TCF while the product still wants National or supported state sections on <code>gpp</code> / <code>gpp_sid</code>. We walked through that mix-up on <a href="https://pixellint.org/blog/cm360-gpp-national-v2/">CM360 GPP National v2 versus <code>us_privacy</code></a>.</p>
<p><strong><code>regs.gpp_sid</code> without <code>regs.gpp</code> on the bid.</strong> Diff tools flag it as incoherent OpenRTB: you told the exchange which GPP section is in force but did not ship the string. Prebid Server and exchange normalizers do not always drop both fields together; one side of the hop can inherit a section id from a template while the GPP body was stripped for size. Buyers read that as "restrict processing" with no payload to parse.</p>
<h2>   How you catch it </h2>
<p>An LLM implementing tag macros or OpenRTB <code>regs</code> can emit plausible key names and still ship the wrong grammar. The RPC or the ad server can return 200. The wire contract does not move.</p>
<p><strong>Pixellint</strong> (<code>cargo install pixellint</code>, <code>npm install pixellint</code>) decodes IAB consent strings on the pixel URL and path-shaped tags instead of treating them as opaque base64. It checks TC version bits, GPP header type, deprecated <code>us_privacy</code>, duplicate signals, and template macros that never expanded. It is independent of IAB Tech Lab and of AAO; it is the deterministic check on the string your tag actually fired.</p>
<p>Paste a live URL into the <a href="https://pixellint.org/">playground</a> or run CLI validation in CI on exported tag templates before traffickers clone them across regions.</p>
