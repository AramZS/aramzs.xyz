<p>Google has added an <a href="https://developers.google.com/search/docs/essentials/spam-policies#back-button-hijacking-faq">FAQs section</a> on the <a href="https://www.seroundtable.com/google-back-button-hijacking-policy-41155.html">back button hijacking spam policy</a> within the spam policies document. Currently, there are five questions and answers in this document and they include:</p>
<p>(Q) Some back button hijacking was caused by third-party advertising platforms. Are you preventing sites from importing code hosted by advertising platforms?<br/>
 (A) No, site owners can continue to work with advertising platforms and import code that they host. We only take action on pages that exhibit back button hijacking behavior.</p>
<p>(Q) Can users report sites that engage in back button hijacking?<br/>
 (A) Yes, users can report potential spammy behavior through the spam submission report.</p>
<p>(Q) Does this policy apply to sites in Google Discover?<br/>
 (A) Yes, Discover is a part of Google Search and our spam policies apply to Discover as well.</p>
<p>(Q) Does the back button hijacking policy apply if a user arrives at a website from a non-Search channel (such as social media) and experiences back button hijacking when trying to return to the source?<br/>
 (A) If back button hijacking happens when a user is browsing within a browser, then the policy applies.</p>
<p>(Q) Does the back button hijacking policy apply when a website opens an external app, which then prevents the user from returning to the original destination?<br/>
 (A) No, app navigation and "open in app" behaviors are outside the scope of the back button hijacking policy.</p>
<p>Google <a href="https://developers.google.com/search/updates#added-an-faq-to-the-back-button-hijacking-spam-policy">said</a> they posted this to "answer common questions we've received about the back button hijacking policy."</p>
<p>As a reminder, Google announced this back button hijacking spam policy back <a href="https://www.seroundtable.com/google-back-button-hijacking-policy-41155.html">in April</a>. Google defined back button hijacking as "when a user clicks the "back" button in the browser, they have a clear expectation: they want to return to the previous page. Back button hijacking breaks this fundamental expectation. It occurs when a site interferes with a user’s browser navigation and prevents them from using their back button to immediately get back to the page they came from. Instead, users might be sent to pages they never visited before, be presented with unsolicited recommendations or ads, or are otherwise just prevented from normally browsing the web."</p>
