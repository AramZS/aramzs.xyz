<p>Every system in the <code>actor.rpg.stats</code> record lives under its own top-level key — a single record can hold D&amp;D, Cyberpunk 2020, Mage, and RPG Maker stats at the same time, without conflict. You only implement the fields you need.</p>
<p>This reference covers the field-level structure of every built-in system. All fields are optional unless noted. The schema is designed for forward compatibility — unknown fields are preserved on read, partial records are valid, and new systems are added without breaking existing data.</p>
<p>If you're building a game and want to use one of these systems, or add your own, see the <a href="https://rpg.actor/dev-guide#systems-overview">Game Systems section in the Developer Guide</a>.</p>

<p>Raw lexicon files are available for direct integration:</p>
<p>D&amp;D 5e is the most fully-featured system in the schema. It covers the complete official character sheet across a set of independent sub-objects — <i>you can include only the parts your game actually uses</i>. A record containing nothing but <code>abilities</code> and <code>hp</code> is perfectly valid; there's no obligation to store spell slots just because you have a combat block.</p>
<p>Sub-objects are stored under nested keys within <code>stats.dnd</code>. Ability modifiers and skill modifiers are not stored directly — the UI calculates them from the raw scores and proficiency bonus at read time.</p>
<p><strong>Partial records work fine.</strong> Only store the sub-objects you actually need. The sheet renderer gracefully omits empty sections.</p>

<p>DCC has the most specialized schema in the collection — deed dice, mercurial magic, spellburn, a 0-level funnel, and probabilistic thief skills that scale with level rather than proficiency. It reflects a deliberately different mechanical philosophy from 5e.</p>
<p>Level 0 funnel characters are fully supported — <code>identity.level</code> starts at 0. Class feature blocks are conditional: populate only the block matching your character's class, and the sheet renderer will show only that section.</p>
<p><strong>Demihuman classes:</strong> Dwarves use the <code>warrior</code> block; Elves use the <code>wizard</code> block. This matches how their abilities are structured mechanically in the rulebook.</p>

<h3>Text Fields <code>dcc.*</code></h3>
<p>A full Cyberpunk 2020 sheet for Night City operators. It covers all nine STAT scores, every skill across the attribute groups, the wound track by severity level, armor by hit location zone, weapons, a ten-slot cyberware roster, and a notes field.</p>
<p>Stats are stored as integers (0–10). Humanity is a string rather than an integer to support the <i>current/base</i> format common in CP2020 sheets (e.g. <code>"38/40"</code>). Skills that derive from an attribute base display as a ratio in the UI but are stored independently.</p>

<h3>Notes <code>pathfinder.notes</code></h3>
<p>A complete Starfinder 2nd Edition character sheet, built on the same structural foundation as the Pathfinder 2e sheet. The key differences are: the skill list adds <code>computers</code> and <code>piloting</code>; weapon proficiencies extend to <code>small-arms</code>, <code>longarms</code>, and <code>heavy</code>; money uses <code>credits</code> and <code>upb</code> (Unit of Processing Base) instead of coinage; and the conditions list adds <code>glitching</code>, <code>suppressed</code>, and <code>untethered</code> for tech-specific states.</p>
<p><strong>Same proficiency values as Pathfinder:</strong> <code>untrained</code>, <code>trained</code>, <code>expert</code>, <code>master</code>, <code>legendary</code>.</p>

<p><code>stats.rmmz</code> — Standard engine parameters</p>

<p>The original catch-all key from before dedicated system keys were added. The <code>stats[]</code> array accepts any named stat with an optional range and category grouping. It still works, but <i>new integrations should use their own top-level key</i> — the <code>custom</code> key is limited to a single system definition in one record.</p>
<p>The <code>custom</code> key is supported for backwards compatibility but should not be used for new systems. Use a unique top-level key like <code>mygame</code> instead — see the <a href="https://rpg.actor/dev-guide#systems-keys">System Keys</a> section of the Developer Guide.</p>
